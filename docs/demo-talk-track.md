# Booth Demo Talk Track: Support Agent in 3 Minutes

The driver script for dry runs and booth handoffs. The demo is one full-screen
app at `/`, built on a fixed 1920×1080 stage that scales to any display. It
has one story at two depths. Everyone sees the same five screens; press `U`
for "Under the hood" and engineers also get the code and the technical line.

## Positioning

- Event: [EVENT NAME], [DATES], booth [BOOTH #].
- Problem we address: eng teams want to ship agents, fast. Keeping async code
  reliable and effective is a heavy lift, especially while models, prompts,
  and patterns keep changing.
- Point of view: engineers should not have to build extra infrastructure to
  know their product works. When durability is defined in code, the data
  needed to observe and improve it is generated by default.
- Tagline: **Unbreakable agents, invisible infra.**
- Pillars, one per screen: **Durable execution → Observability → A/B testing.**

## The Scenario

An AI customer-support agent answers one ticket in six durable steps:

1. Read ticket
2. Look up customer
3. Look up order
4. Draft reply
5. Policy check
6. Send reply

The order API returns a 503 once, and Inngest retries that step alone. The
visitor picks the ticket, votes on the reply, and watches a model split test
pick a winner.

## Marketing-Safe Status

- **Real:** the Inngest function, durable steps, the 503 retry and memoized
  replay, the captured trace, `step.score` (cloud mode), and
  `group.experiment` traffic splitting.
- **Synthetic booth props:**
  - the tickets, customer and order data;
  - the drafted reply (canned unless `OPENROUTER_API_KEY` is set);
  - the per-model quality scores, so the split-test winner is scripted;
  - the model pricing behind every $ figure.

Safe summary line:

> Durability is defined in code, so the data to observe and improve the agent
> is generated by default. You just watched it survive an outage, show its
> work, and get measured.

If the screen shows the coral **Replay** chip, the live run was unavailable
and you are watching a labelled replay of the same run shape. Say so ("this
one is a replay, the booth Wi-Fi is fighting us") and keep going.

## Setup

- One large TV, 1080p, full-screen browser (`F11` / `⌃⌘F`) on `/`.
- The driver keeps a keyboard or clicker. The visitor taps a ticket card, or
  says a number and the driver presses it.
- The Inngest dashboard is not on screen by default. `D` opens this run's
  trace (or the experiment, on the A/B screen) in its own window, as proof
  when someone asks.

## Keys

| Key | Action |
| --- | --- |
| `1` `2` `3` | Pick a ticket (start screen) · vote Good / Needs work (A/B screen) |
| `Space` / `Enter` | Primary action: start, run the split test, next |
| `→` / `←` | Next / back (moves between tickets on the start screen) |
| `U` | Under the hood: code drawer plus technical lines |
| `F` | Toggle the order-API outage (on by default; takes effect on the next run) |
| `D` | Open this run in Inngest |
| `R` | Reset to the start screen |
| `?` | Key overlay |

The bottom-left HUD shows elapsed time (it turns coral after 4:00), which
screen you are on, run status, and whether the outage is armed. It also has
an **Under the hood** button if you forget `U`. The screen buttons stay
greyed out until a ticket is picked.

Every screen after Start has a **View trace in Inngest** button (top right)
for the live run. Once the split test has run, a **View split test in
Inngest** button appears too. Neither shows on a Replay, because there is no
real run to open.

## Opener

> How are you keeping your agents reliable today, while the models and
> prompts keep changing underneath them?

Engineer, or asks "how"? Press `U` before picking a ticket and run the
5-minute path. Otherwise run the 3-minute path; you can press `U` at any
point if a question turns technical.

## 3-Minute Path (business default)

| Screen | Do | Say |
| --- | --- | --- |
| Start (15s) | Visitor picks a ticket. | "This is an AI support agent. Pick a customer." |
| Durable (60s) | Watch. | "Six steps. Watch the order lookup… the order system just went down. Inngest waits and retries only that step. The first two weren't re-run, so there's no repeat model spend, and the customer gets their answer." |
| Observe (45s) | `→` | "Nobody wrote logging for this. Every step, the retry, tokens and cost are captured by default. When a customer asks what happened, the answer is already here." |
| A/B test (60s) | `→`, then visitor presses `1` or `2`. `Space`, `Space`. | "Was that reply good? Your vote is now a metric on that exact run. Would another model do better? We split real tickets between two models and score every answer. The data picks the winner." |
| Recap (20s) | `→` | "Durable, observable, measured. At this volume that's this much a month. Scan to build it yourself." |

## 5-Minute Path (engineer, `U` on)

The same beats. The drawer on the right shows the code for each screen, so
point at it rather than describing it.

- **Durable.** "Each `step.run` is a durability boundary. The 503 retries
  only `lookup-order`. The steps before it are replayed from memoized state,
  not executed. Retries and backoff are config on the function, not code you
  maintain."
- **Observe.** "Inputs and outputs per step, the failed attempt in red, the
  wait before the retry. OTel spans for the model and API calls. Insights
  queries all of it with SQL." Press `D` if they want the real trace.
- **A/B test.** The drawer follows the panel:
  - Vote: "`step.score` attaches the vote to this run id. A person, a
    business rule, or an LLM judge all score the same way."
  - `Space`: "`group.experiment`. A variant is just a function, so this
    splits prompts, retrievers or vendors the same way. Here it's a 50/50
    weighted split, and every score lands on the variant that produced it."
- **Recap.** The primitives strip: Event, Function, Step, Metric, Experiment.

## Claims To Avoid

- Do not present the split-test winner as a real model benchmark. It is a
  scripted booth result; the traffic split mechanism is what is real. The
  model names come from `NEXT_PUBLIC_DEMO_MODEL_*`, and the challenger wins
  whichever models are configured.
- Do not present $ figures or the monthly saving as real pricing. The
  screen labels them "illustrative".
- Do not imply the reply comes from a real LLM unless OpenRouter is
  configured (`/api/demo/status` reports `llm.mode`).
- Do not call a Replay-tagged run live.

## Dry-Run Acceptance

- A driver completes the 3-minute path in ≤ 3:30 and the 5-minute path in
  ≤ 5:00, by keyboard only, on the booth TV.
- The 503 lands on "Look up order", the countdown runs, and the retry
  recovers with the first two steps marked "Not re-run".
- No Replay chip while Inngest is reachable.
- `npm run demo:preflight` and `npm run demo:smoke-loop` pass against the
  final demo URL.
- 2-3 drivers are signed off (`docs/driver-card.md`).
- A contingency recording exists (`docs/contingency-recording.md`).

## If Something Breaks

- **Replay chip showing.** The live run did not start within 5s, or it
  stalled for 25s. The demo continues on a labelled replay; narrate it
  honestly. Check `/api/demo/status` between visitors.
- **Split test tagged Replay.** The batch did not land within 15s. Same rule.
- **Anything weirder.** Press `R`, pick a ticket again.
- **Network or Cloud auth down for good.** Switch to the contingency
  recording.
